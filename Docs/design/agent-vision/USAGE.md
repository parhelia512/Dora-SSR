# Dora Agent 游戏画面检查

在 Agent 的现有模型配置中使用已支持的官方 DeepSeek 服务或国内 GLM Coding Plan 服务，即可使用默认视觉能力，无需新增视觉模型配置。

可以直接提出：

> 运行当前游戏，检查开场画面的角色、HUD、平台和文字是否清楚，有没有裁切或遮挡。结合源码调整确实存在的问题，修改后重新截图对比。

代码模式下，Agent 构建游戏后通过 `preview_game` 启动入口、取得 1—3 张游戏画面并结束此次预览；Remix 可以保持可见。`analyze_image` 读取这些图片并返回文字观察。主 Agent 结合源码中的布局、相机和坐标决定改动，再构建、取景对比。计划模式只能分析已有图片，不启动游戏。

Web IDE 和 Remix 的工具步骤显示图片、实际视觉模型与分析报告；点击缩略图可放大。历史图片可在重启、压缩后重新分析；图片被删除或损坏时会明确失败或显示缺失占位。

首版默认路由：

| 当前 Agent 服务 | 看图模型 |
| --- | --- |
| 官方 DeepSeek | `deepseek-v4-flash-vision-exp` |
| 国内 GLM Coding Plan | `glm-4.6v` |

未知服务或自定义网关不自动启用看图，也不会切换到其他供应商。GLM 的实际 API 请求已验证，尚未核查其账单是否计入 Coding Plan 套餐额度。

模型负责定性观察，不负责精确像素测量。单张图不能证明移动、碰撞或输入正确；文字识别和遮挡判断也可能出错，主 Agent 应核对源码并复拍。

内部默认上限为长边 1280、每次 1—3 张、每张 4 MiB。每任务最多 12 次分析尝试；已报告累计用量达到 60000 token 后不再发新请求。这些是工程限额，不是图片质量评分或精确费用承诺。

本轮已验证 macOS 本地引擎、Web IDE 和 Remix。移动真机按用户要求延期，其他平台尚未验证。详细结果见 [评测](./EVALUATION.md) 与 [验收审计](./ACCEPTANCE-AUDIT.md)。
